Getting started

Introduction

@beetlio/connect is a Beetl project for defining host-neutral data integrations. Its SDK runs inside compatible host applications without depending on Beetl services or infrastructure; a companion CLI supports local development and testing.

Experimental

The project is currently version 0.0.0. Public APIs and local storage formats may change.

Responsibility boundaries

An integration defines provider-specific behavior. A host supplies execution services and keeps credentials outside the sync context.

Integration

  • Credential and configuration schemas
  • Connection verification
  • Record schemas and primary keys
  • Provider requests and pagination strategy
  • Checkpoint shape and update logic

Host

  • Credential storage and request authentication
  • Retries and cancellation
  • Record and checkpoint persistence
  • Snapshot commit or rollback
  • Logging

Installation

Node.js 24 or newer is required. The package has one runtime dependency, Zod.

Project-local SDK and CLI

Install the SDK and a project-local CLI in your integration project:

npm install @beetlio/connect

Run the local command with npx beetl-connect.

Global CLI

To make beetl-connect available system-wide, install the same package globally:

npm install --global @beetlio/connect

Authoring an integration

An integration default-exports the result of defineIntegration(). The following example defines an unauthenticated connection and one snapshot sync.

import { auth, defineIntegration, z } from "@beetlio/connect";

const Item = z.object({
  id: z.string(),
  name: z.string(),
});

export default defineIntegration({
  key: "example",
  displayName: "Example",
  connection: {
    baseUrl: "https://api.example.com",
    auth: auth.none(),
    async verify(ctx) {
      const response = await ctx.fetch("/health");
      if (!response.ok) throw new Error("Verification failed");
    },
  },
  syncs: (defineSync) => [
    defineSync({
      key: "items",
      displayName: "Items",
      mode: "snapshot",
      records: Item,
      primaryKey: ["id"],
      async run(ctx) {
        const response = await ctx.fetch("/items");
        const records = z.array(Item).parse(await response.json());
        await ctx.emit({ records });
      },
    }),
  ],
});

Provider request boundary

Paths passed to ctx.fetch() must be relative to the configured origin and begin with /. Absolute and scheme-relative URLs are rejected.

Runtime validation

Connection configuration, sync configuration, credentials, records, and checkpoints are parsed with their declared Zod schemas before crossing host boundaries.

Embedding Connect in a host application

Applications execute integrations through the runtime exported from @beetlio/connect/host. The CLI uses the same host contract and is not required at runtime.

import { runSync, verifyConnection, type SyncHost } from "@beetlio/connect/host";
import integration from "./integration.ts";

const host: SyncHost = applicationHost;
await verifyConnection(integration, { connectionConfig }, host);
const result = await runSync(
  integration,
  "items",
  { connectionConfig, syncConfig, checkpoint },
  host,
);

A host implements provider requests, authentication, record and checkpoint persistence, and logging. Snapshot syncs additionally require beginSnapshot, commitSnapshot, and abortSnapshot. Persist the checkpoint returned by runSync() and provide it to the next incremental run.

The custom host example implements the complete interface and executes the Wikidata integration without the CLI.

Authentication

Authentication is declared on the connection. The host reads the referenced credential fields and modifies provider requests.

TypeDeclarationRequest behavior
Noneauth.none()No credentials added
Bearerauth.bearer()Adds an Authorization bearer token
Basicauth.basic()Adds HTTP Basic authentication
API keyauth.apiKey(...)Adds a header or query parameter
Customauth.custom(...)Maps multiple credential fields to headers or query parameters
OAuth 2.0auth.oauth2AuthorizationCode(...)Uses an access token and can refresh after a 401
Transport requirement

Authenticated requests require HTTPS. Loopback HTTP is allowed for local tests and fixtures.

Credential environment variables

The CLI maps camel-case credential fields to upper-snake-case environment variables. For example, apiKey maps to API_KEY.

set -gx API_KEY "<api-key>"
npx beetl-connect verify
set -e API_KEY

Sync behavior

Append syncs

Append is the default mode. Each emitted batch is appended to the output file. If the sync declares a checkpoint schema, the latest emitted checkpoint is persisted and can be supplied to the next run.

Snapshot syncs

A sync with mode: "snapshot" writes to a temporary file. The host replaces the previous output only after the run and all pending host operations succeed. Snapshot syncs cannot declare checkpoints.

Pagination

ctx.paginate() supports cursor and offset pagination. It validates page records before yielding them. Integrations can use ctx.fetch() directly when a provider requires a different strategy.

Retries

The local host retries safe methods for common transient HTTP statuses and transport failures. A connection can override or disable the policy.

retry: {
  maxAttempts: 5,
  statuses: [429, 502, 503, 504],
  methods: ["GET"],
  initialDelayMs: 500,
  maxDelayMs: 30_000,
}

Running the Wikidata sync

The entities sync calls Wikidata's wbsearchentities API. It returns search-result metadata rather than complete claims or relationships.

npm run cli -- sync entities \
  --integration examples/wikidata/integration.ts \
  --connection-config '{"userAgent":"my-wikidata-sync/1.0 (me@example.com)"}' \
  --sync-config '{"search":"open source","language":"en","maxResults":25}'

Output record

{
  "id": "Q39162",
  "label": "open source",
  "description": "philosophy about free redistribution and access to a product",
  "aliases": [],
  "url": "https://www.wikidata.org/wiki/Q39162"
}

maxResults defaults to 100 and accepts values from 1 through 500. pageSize defaults to 25 and accepts values from 1 through 50.

Wikidata structured data is available under CC0. Automated clients must follow Wikimedia's API usage guidelines.

Current scope

The local host currently supports one OAuth connection per integration. The following capabilities are not implemented:

  • Hosted sync execution
  • Multiple named connection profiles
  • Encrypted local credential storage
  • Integration deployment or compatibility manifests
